# 安装并上手 Codex

这一步你会安装 Codex 并跑通第一个任务。Codex 是 OpenAI 出的编码智能体，直接在
你的电脑上运行：你用自然语言描述要做什么，它读取项目、想清楚怎么做，然后读取、
修改并运行代码来完成。官方文档在 [developers.openai.com/codex](https://developers.openai.com/codex)，
源码仓库在 [github.com/openai/codex](https://github.com/openai/codex)。

这一课的目标，是让你亲手装好它、发出第一个任务，并看懂它是怎么工作的。

## 先确认你的工具

Codex 通过终端运行，所以先确认你已经有可用的终端，并且装好了 [Git](https://git-scm.com)。
在终端里运行下面两条命令，确认它们都能用：

```bash
git --version
node --version
```

`git --version` 打印出版本号就说明 Git 可用。`node --version` 是可选的，能用就说明
你已经装了 Node.js。注意，Node.js 不是可有可无的：后面几课用 Node 内置的测试模块
做示例项目，也需要它来用 npm 方式安装 Codex，所以请确认它能正常打印版本号。两条命令
都不报错，就可以继续。

## 安装 Codex

Codex 支持多种安装方式，按你的系统选一种。

macOS 或 Linux，用官方安装脚本：

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

Windows 用 PowerShell：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

如果你更习惯用包管理器，也可以选这两种之一。用 npm：

```bash
npm install -g @openai/codex
```

用 Homebrew（macOS）：

```bash
brew install --cask codex
```

> 提示：如果你所在的网络需要代理，先让终端能正常访问外网，再运行安装命令。

装完后，在终端运行下面这条命令确认安装成功：

```bash
codex --version
```

它会打印出 Codex 的版本号。看到版本号，说明安装完成。

## 登录

第一次运行 `codex` 时，它会引导你登录。推荐用 **Sign in with ChatGPT**，用你的
ChatGPT 账号（Plus、Pro、Business、Edu 或 Enterprise 计划）即可，这是最省事的方式。

```bash
codex
```

如果你没有可用的 ChatGPT 计划，也可以用 API key，但这需要额外配置，参见官方的
[认证文档](https://developers.openai.com/codex/auth)。对这门课来说，推荐先用 ChatGPT
账号登录。

登录这一步不要跳过。没有登录，Codex 无法工作。

## 跑通第一个任务

现在新建一个空目录作为练习目录，并进入其中，后续练习都在这里做，别动你已有的
真实项目：

```bash
mkdir codex-practice
cd codex-practice
```

在这个目录里，给 Codex 第一个任务：让它创建一个打印问候语的小脚本。下面是一个
默认示例，脚本会打印一行问候语。

```text
创建一个 Bash 脚本 greet.sh，运行它时打印一行问候语，例如 "Hello from Codex"。
并让它可以直接运行。
```

把这条任务发给 Codex，看它怎么做。在发送之前，先猜一猜：Codex 大概会做哪几件事？
它会先做什么、再做什么？把你的猜测记在心里或写下来，等它做完再对照。

Codex 通常会先看看当前目录里有什么，然后创建文件、写入内容，并运行脚本验证。注意
它做的每一步：它怎么判断要做什么、怎么把想法变成文件、怎么确认结果。这就是智能体
的"读取、思考、修改、运行"循环。

## 检查你做的脚本

任务完成后，自己验证一下结果，不要直接相信 Codex 说它做完了。打开终端，运行：

```bash
./greet.sh
```

如果脚本打印出的正是你要的那行问候语，任务就真的完成了。如果它没运行、报错，或
输出不对，那就是还没完成，继续让 Codex 修复，直到脚本能运行且输出正确。

## 理解这个循环

回头看刚才的过程，Codex 做的一系列动作可以归成四步：

- **读取**：看目录里有哪些文件、任务要求什么。
- **思考**：决定先做什么、怎么做、用什么方式。
- **修改**：创建或改动文件，把想法落到代码里。
- **运行**：执行命令或脚本，验证结果是否符合要求。

这四步会反复循环，直到任务完成。你在后面每一课里，都会反复看到这个循环。你要做的，
是把任务说清楚、在关键选择上做决定，并核对它每轮的结果。

## 尝试改一改

脚本跑通之后，自己动手改一点东西，看看 Codex 怎么响应。比如让它把问候语改成你
自己的名字，或多打印一行内容：

```text
把 greet.sh 的问候语改成我的名字，并再打印一行今天想说的话。
```

看 Codex 是只改了需要改的地方，还是动到了不该动的内容。运行脚本，确认改动生效、
输出正确。
